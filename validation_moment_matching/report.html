ExTrack · branch fusion

The fused Gaussian was too narrow

ExTrack collapses branches of the tree of states into one Gaussian at every step. It matched the mean of the mixture but dropped the spread of the branch means, so every fused message was over-confident. Here is the correction, the evidence that it helps, and a second, much cheaper way to organise the same buffer, transposed from ExaTrack.

What the fusion was doing

one missing term

At each step the recursion carries, per track and per sequence of states b, a log weight LP_b and a Gaussian N(r; m_b, s2_b) over the current position. Branches that became nearly equivalent are fused, i.e. a mixture is replaced by a single Gaussian. fuse_tracks_th took a weighted average of both the means and the variances:

mu_j   = sum_b w_b m_bj
sig2_j = sum_b w_b s2_b      ← only the within-branch half

The mean is right. The variance is the law of total variance, and only its first half was there. The spread of the branch means was dropped, so the fused Gaussian was systematically too narrow and the recursion behaved as if the particle's position were known better than it is. fuse_gaussians now computes, per spatial dimension and with scalar formulas only:

LP     = log sum_b exp(LP_b)
mu_j   = sum_b w_b m_bj
sig2_j = sum_b w_b s2_b + sum_b w_b (m_bj - mu_j)**2

No covariance matrix is ever formed, so the message stays in the family the recursion propagates — a mean and a variance per dimension, which log_integrale_dif already accepts. The only part of the exact second moment that is dropped is the off-diagonal, which would need a matrix formulation. set_fusion_method(moment_matching=False) restores the old behaviour for A/B runs.

How the claim is checked

Switching the fusion off leaves ExTrack's likelihood exact — it is the only approximation in it. That fusion-free mode agrees to 1e-14 with an independent brute-force enumeration of all 2**T state sequences, written with matrices so it shares no code with the recursion. Every number below is measured against it.

Where the model is identifiable the two fusions are indistinguishable. Above d1 = 0.75 × LocErr, both recover the diffusion length to within 0.8 %, the localization error to within 0.4 % and the transition probabilities to within 1 %; the residual scatter comes from the 7-point tracks, not from the fusion.

At d1 = ½ LocErr the difference is large. There the two states are barely separable, the likelihood surface is nearly flat, and the legacy fits run away: the transition probabilities come back almost four times the truth. With moment matching the same data, the same starting point and the same optimizer give +42 % and +13 %. It also halves the bias on the mobile fraction. This is exactly the corner where an over-confident position message is fatal: the recursion pays too much attention to a difference that is really localization noise, and explains it by inventing transitions.

State annotation, at the true parameters, is unchanged — both fusions sit 3.2e-3 in mean absolute deviation from the exact posterior. At each mode's own fitted parameters the moment-matched posterior is 1.07× closer to exact, its log loss 0.5 % lower and its accuracy 0.35 % higher, which is the parameter improvement propagating rather than a separate effect.

A cheaper buffer, from ExaTrack

4.7× per likelihood

ExTrack keeps one hypothesis per sequence of states over the last frame_len frames — nb_states ** frame_len of them — and prunes them back at every step with a python grouping loop of cost O(n²) whose outcome depends on the data. ExaTrack organises the same information differently: a fixed buffer indexed by (steps since the last transition, current state), the oldest slab meaning "at least that old".

Per track and per step, at 3 states.
schemehypothesesbranches / stepgrouping
sequences (current)nb_states ** frame_lennb_states ** (frame_len+1)python loop, O(n²), data dependent
ages (new)frame_len × nb_statesframe_len × nb_states²none, the layout is static

It is available as param_fitting(…, sequence_scheme='ages') and predict_Bs(…, sequence_scheme='ages'); the default is unchanged. Every fusion inside it is the moment matched one, which matters more here than in the historical scheme because the newborn fusion pools hypotheses whose means are genuinely far apart. Two properties are asserted by the test suite rather than assumed: when all states share one diffusion length every fusion is between identical Gaussians, and the scheme then reproduces the exact likelihood and the exact state posterior to 1e-14; and the buffer really is frame_len × nb_states at 2, 3 and 4 states.

The 'ages' error saturates at frame_len = 4 and a longer memory buys nothing — 12 age slabs give the same answer as 4. So the savings cannot be spent on a deeper buffer. What it is missing is not age resolution but the identity of the state before the current segment: with three states, a particle arriving in state j could have come from either of the other two, and the newborn fusion pools two genuinely different Gaussians. That is precisely what ExaTrack's nb_kept_transitions option fixes — remember the previous state as well, buffer frame_len × nb_states² — and its own benchmark measures 3–5× from it at three states and almost nothing at two. Note also that the 'ages' error grows with the state separation k while the sequence error is flat: the same signature ExaTrack records, that what drives a fusion error is how dissimilar the pooled Gaussians are.

Two things worth knowing

traps
  • sim_noBias does not simulate ExTrack's model. It splits every frame into 30 substeps, so a transition can happen anywhere inside a frame and a particle can even switch twice; the frame-level model cannot represent that and absorbs it as extra transitions. Measured: a requested p = 0.1 comes back as 0.14 from a fit — with the exact, fusion-free likelihood. The mismatch is identical for every fusion mode but it dominates the distance to the truth, which is why the sweeps here draw tracks from the frame-level model instead.
  • get_pos_PDF assumed one variance for all dimensions. A moment matched fusion returns one variance per dimension, and a hardcoded reshape(…, 1) in refined_localization broke on it. Fixed by keeping that width dynamic, which also removes a silent mishandling of per-dimension localization errors that was already there.

Nothing is committed; the working tree carries the changes. Existing behaviour is preserved by default for the buffer scheme and changed by default for the fusion — that one is a correctness fix, so the old formula is reachable only through set_fusion_method.

Measured on 5 000-track data sets drawn from ExTrack's own generative model, 2 spatial dimensions, dt = 0.02 s, no bleaching and no field-of-view term, so the fusion is the only approximation left in the likelihood.
